# 个人知识管理工作流

## 1. 从收藏到可用

个人知识管理最常见的问题不是“没有资料”，而是“收藏了但不再打开”。知屿的使用原则是：每份资料进来时就想清楚它可能在什么问题下被用到，然后让系统负责在那一刻把它找出来。

一个轻量工作流：

1. **收集**：把 PDF、网页摘录、截图统一放进一个待整理文件夹。
2. **命名**：文件名包含主题和日期，例如 `2026-10-RAG评测方法.md`，方便 BM25 精确命中。
3. **导入**：上传后检查解析状态，扫描件确认 OCR 是否提取到文字。
4. **提问**：先用自然语言问，不要刻意堆关键词；系统会做改写和多路召回。
5. **复盘**：每周看一次低置信度问题和引用核查失败的记录，补文档或改问法。

## 2. 文档命名与结构

文件名是最便宜的元数据。推荐“日期-主题-类型”的格式，例如：

- `2026-09-混合检索调参记录.md`
- `2026-10-RAGAS指标速查.pdf`
- `架构图-在线检索链路.png`

文档内部尽量使用清晰的标题层级。解析器会把标题写入 heading_path，检索时“章节名 + 正文”一起参与匹配，比一整篇没有结构的长文更容易被准确召回。

## 3. 提问方式

- 事实型：“索引版本号保存在哪个字段？”
- 方法型：“图片里的表格怎么提取？”
- 对比型：“重排前后有什么差异？”
- 总结型：“总结一下评测那篇笔记的结论。”
- 元问题：“知识库里有哪些文档？”

追问时可以自然使用“它”“这个方案”，系统会结合最近对话补全主题。但如果话题切换很大，建议重新说清楚对象，避免错误指代。

## 4. 维护节奏

- **每日**：导入当天新增资料，确认状态为 ready。
- **每周**：清理重复文档，修复解析失败的文件，查看评测历史。
- **每月**：回顾低分问题，补充缺失资料；如果换了 embedding 模型，执行一次向量修复。
- **每季度**：导出重要文档，检查备份；清理不再需要的会话和缓存。

## 5. 隐私与边界

个人知识库可能包含私人笔记、合同或工作资料。部署时优先选择本地运行：SQLite、Chroma 和上传文件都保存在本机 `data/` 目录。只有配置在线 LLM 时，问题、检索到的片段和对话历史才会发送给模型服务商。敏感资料可以只使用离线模式，或选择支持私有化部署的模型端点。

## 6. 不要把 RAG 当搜索引擎

RAG 的价值不是“返回十个链接”，而是“读完资料后给出一个可核对的答案”。因此每次回答都应该看三样东西：结论是否直接、引用是否真的支持这句话、置信度是否合理。如果引用卡片和结论对不上，宁可继续追问，也不要直接相信一段流畅的文字。

好的知识库不是一次建成的，而是在“提问—发现缺口—补充资料—再提问”的循环里逐渐长出来的。
